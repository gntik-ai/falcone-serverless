# ctr-worker-execution-api v1

Contract: ctr-worker-execution-api
Version: 1

This is the base execution API between the dispatcher and an execution worker
(RUN-01.t1, FR-RUN-01, FR-RUN-02). It carries every ADR 0010 D1 field so that INV-01,
RUN-02 and OCI-04 extend it additively. It is a contract only: it adds no OCI execution, no
transport and no dispatcher. The [OCI profile](oci-profile.md) is a separate profile of this
contract for mode `oci` and is unchanged.

The Rust types are `worker/src/api`; `parse_request`, `parse_result` and
`admit_wasm_attempt` are the entry points. The conformance suite is
`worker/tests/execution_api_contract.rs` over `worker/tests/fixtures/contract`. These tests
execute no guest code and do not touch the cluster. The pinned sources and fixtures, with
their sha256 values, are recorded in the [contract inventory](../falcone-contract-inventory.md)
(section "Worker execution API").

Assumptions still open: ADR 0006 (execution credential format) and ADR 0009 (Falcone is
authoritative for revision and activation state) are Proposed. v1 follows both and does not
claim them accepted.

## Conventions

- JSON objects are closed: an unknown member is malformed. Names are `snake_case`, except the
  invocation identity, whose names are the WIT function names (`invocation-key`,
  `attempt-id`, `idempotency-key`).
- **Absent is not `null`.** A member whose contract says "absent" (the projection `base`,
  `identity.base_digest`, `result`, `failure`, `failure.code`, progress `percent`) is either
  absent or carries a value. An explicit `null` is malformed in every case.
- Digests are `sha256:` followed by exactly 64 lowercase hex digits.
- **No request-controlled text in any error output.** `activation_id`, `attempt_id`,
  `projection.revision` and every other request string appear in `Debug`, `Display`, logs and
  messages only as `<redacted>`. Parse errors carry an enum, never serde's message, which
  quotes the input. Request-derived enums and validated codes may be printed. Serialized
  results keep their contract fields; only formatted text is redacted. Never print a request
  field to help debugging.
- Evolution is additive. A later minor revision adds optional members only; a required member
  or a changed meaning is a new major version. Consumers pin the version.

## Execute attempt

The dispatcher sends one execute request per attempt of an activation.

| Member | Meaning |
| --- | --- |
| `activation_id` | Non-empty activation ID, stable across attempts. |
| `attempt_id` | Non-empty ID of this attempt. |
| `attempt_number` | Integer of at least 1; 1 for the first attempt. |
| `deadline_ms` | Absolute deadline in integer milliseconds in the dispatcher's clock domain. |
| `invocation` | Invocation identity: `invocation-key`, `attempt-id`, `idempotency-key`. |
| `credential` | `{claims}`: the `ctr-execution-credential` v1 claims. |
| `projection` | The pinned revision projection. |
| `params` | The legacy `main(params)` envelope object, unchanged. |

Consistency rules, enforced by `parse_request`: `invocation.attempt-id` equals `attempt_id`;
the claims `activation`, `attempt` and `revision` equal `activation_id`, `attempt_id` and
`projection.revision`; `iat` is not after `exp`; every `allowed_capabilities` entry is also in
`projection.capabilities` (the credential never allows more than the projection grants).

### Execution credential

`credential.claims` has exactly the members of `execution-credential.v1.claims.schema.json`
(`iss`, `aud`, `tenant`, `workspace`, `pool_profile`, `revision`, `activation`, `attempt`,
`iat`, `exp`, `allowed_capabilities`), all required. v1 binds to that contract and does not
carry the credential as an opaque string. Signature and encoding of the token are defined by
that contract, not here. `allowed_capabilities` entries are capability grants and are opaque
objects to this contract. The claims are credential material: they are held in redacting
types and never printed. Do not log a request.

### Invocation identity

The legacy invocation identity maps to the `falcone:host/invocation-context` functions
`invocation-key`, `attempt-id` and `idempotency-key` (`worker/wit/host.wit`). The legacy
envelope and invocation-identity fixtures are the ones inventoried in the contract inventory
(`docs/contracts/fixtures/legacy-envelope`), used in place, byte for byte, and round-trip
through `Params`, `InvocationIdentity` and `HandlerResult` unchanged.

## Revision projection v1

| Member | Meaning |
| --- | --- |
| `revision` | Non-empty function revision ID. |
| `runtime_mode` | Required. `wasm` or `oci`. Missing, unknown or `null` is malformed. |
| `base` | The pinned base (below); absent when the revision pins none. |
| `artifact_digest` | Digest of the raw validated artifact. |
| `component_digest` | Digest of the component the worker compiles. |
| `language_profile` | `{name, version}`: an exact approved profile pin. |
| `engine_version`, `wasi_version`, `interface_version` | Exact pinned versions. |
| `imports` | Declared imports, non-empty names. |
| `budgets` | Positive integers `fuel`, `memory_bytes`, `timeout_ms`, `max_host_calls`. |
| `capabilities` | Granted capabilities, opaque grant objects. |

v1 requires every member for both modes. OCI-only members (function image digest, container
contract and shim versions) are optional additions of OCI-04.

### Base

`base` is a tagged union on `kind`:

- `{"kind": "catalog", "id", "version", "digest"}`: `id` is lowercase letters, digits, `.`,
  `_` or `-`, without `@`; `version` is an exact `MAJOR.MINOR.PATCH` (optionally `-pre`,
  `+build`); `digest` is the base digest.
- `{"kind": "byo", "image_digest", "signer_identity", "attestation_ref"}`.

`base` is absent when the revision pins no base. It is never an unresolved default alias: a
`kind` other than `catalog` or `byo`, a version such as `latest`, `default`, a range or a
partial version, a missing digest, or `null` is malformed.

## Result

A result is the legacy `{status, result, logs}` envelope with the failure class and the
activation runtime identity:

| Member | Meaning |
| --- | --- |
| `activation_id`, `attempt_id` | Must equal the request's. |
| `status` | `success` or `error`. |
| `result` | The legacy handler return value (an object, for example `{statusCode, headers?, body?}`). Present on success, absent on error. |
| `logs` | Required array of log lines, possibly empty. |
| `failure` | `{class, code?}`. Present on error, absent on success. |
| `identity` | Required activation runtime identity block. |

`parse_result(request, bytes)` is the entry point for the dispatcher. It rejects a result whose
status and members disagree, whose correlation or identity does not describe the request, or
whose coded failure carries another class than the table below.

### Activation runtime identity

Every result, including a refusal, carries `identity`: `function_revision`, `runtime_mode`,
`artifact_digest`, `base_digest`, `wasmtime_version`, `language_profile` and
`interface_version`. Everything but `wasmtime_version` must equal the projection.
`base_digest` is present exactly when the projection pins a base, and then equals that base's
digest (`digest` for catalog, `image_digest` for byo). It is **absent**, never `null`, when no
base is pinned. `parse_result` rejects a pinned base without `base_digest`, a `base_digest`
(value or `null`) without a pinned base, and `null` with a pinned base.

## Failure classes and codes

| Class | Meaning |
| --- | --- |
| `retryable` | Nothing observable happened; a new attempt may run. |
| `non_retryable` | A retry cannot succeed. |
| `uncertain` | The attempt may have had an external effect; never replay it blindly. |

The class of a code never depends on `attempt_number`: a retried attempt gets the same class.
`code` is absent for a failure with no named code, where the class alone applies. The OCI and
base codes are the `detail.reason` values of `ctr-functions-api` v1 (`failureReason`),
referenced by name and meaning, not redefined here. `runtime_mode_unsupported` is the only
code defined by this contract.

| Code | Class | Source and meaning |
| --- | --- | --- |
| `oci_not_authorized` | `non_retryable` | `ctr-functions-api` v1, gateway `GW_OCI_NOT_AUTHORIZED`: OCI execution is not authorized for the workspace. |
| `base_disabled` | `non_retryable` | `ctr-functions-api` v1, gateway `GW_BASE_DISABLED`: the selected base is disabled. |
| `base_mismatch` | `non_retryable` | `ctr-functions-api` v1, gateway `GW_BASE_MISMATCH`: the base does not match the pinned digest. |
| `runtime_mode_unsupported` | `non_retryable` | Worker only: the Wasm worker received a revision whose `runtime_mode` is not `wasm`. |

`ctr-functions-api` marks `failureReason` extensible; v1 of this contract is closed, so a new
code is a minor revision that consumers adopt by pinning it. Falcone owns the public error
codes (API-01); this contract defines none of them.

### Non-wasm refusal

`admit_wasm_attempt(request, wasmtime_version)` admits a `wasm` attempt (nothing runs at
admission) and refuses any other mode. The refusal is non-retryable at every attempt number and
no execution happens. Its result is `status: error`, no `result`, `logs: []`,
`failure: {class: non_retryable, code: runtime_mode_unsupported}` and the identity of the
revision (`runtime_mode` is the revision's mode). The fixture is
`worker-execution-api/results/refusal-non-wasm.json`.

## Execution updates

The worker sends updates for a running attempt. Every update carries `activation_id`,
`attempt_id` and a `sequence` (integer of at least 0) and a `kind`:

| `kind` | Extra members |
| --- | --- |
| `heartbeat` | none |
| `progress` | optional `percent`, whole number 0 to 100 |
| `checkpoint` | `checkpoint_ref`: a reference to a committed checkpoint object, never its bytes |

## Cancel

Cancel is requested with `{activation_id, attempt_id}`. The worker reports `state`:

| `state` | Meaning |
| --- | --- |
| `requested` | The cancel was received and not yet applied. |
| `acknowledged` | The guest and blocking host calls were told to stop. |
| `uncertain` | The worker cannot say whether the guest stopped or whether external effects happened. |

No state claims that side effects were reversed. Drain semantics and limit-exceeded details are
RUN-02 additions.
